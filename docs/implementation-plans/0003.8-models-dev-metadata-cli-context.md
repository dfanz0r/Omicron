# Implementation Plan 0003.8: Models.dev Metadata and CLI Context Display

Status: **Complete**  
Predecessor: Plan 3.7 complete  
Successor: Plan 4 transaction-backed edit harness  
Closure review: `docs/code-reviews/0083-plan-3.8-closure-verification.md`

---

## Purpose

Plan 3.7 established the model metadata architecture, but it intentionally left `ModelsDevMetadataSource` as a placeholder and the CLI still displays context length from static `Model.ContextWindow` only.

Plan 3.8 makes model metadata useful for the CLI frontend by:

1. implementing `models.dev` metadata loading;
2. mapping context/output/capability metadata into `ModelMetadata`;
3. refreshing catalog metadata through static + `models.dev` sources;
4. exposing effective metadata-backed context lengths in `/model` and `/models`.

This is active implementation work, not a future hardening backlog item.

---

## Current State

Implemented in Plan 3.7:

- `ModelMetadata`
- `IModelMetadataSource`

- `ModelsDevMetadataSource` placeholder returning empty
- `StaticModelMetadataSource`
- `ModelMetadataMerger`

Current gaps:

- `ModelsDevMetadataSource` does not fetch or parse `https://models.dev/api.json`.
- CLI `/model` prints `Model.ContextWindow` directly.
- CLI `/models` does not show context length.
- `IModelCatalog` does not expose metadata, so frontends either need helper methods or must downcast to `ModelCatalogService`.

## External Source: `models.dev`

`models.dev` exposes its public model database at:

```text
https://models.dev/api.json
```

The response is organized by provider and provider-local model ID. Relevant fields include:

- `name`
- `limit.context`
- `limit.input`
- `limit.output`
- capability booleans such as `tool_call`, `reasoning`, `attachment`, `structured_output`, `temperature`
- `modalities.input` / `modalities.output`
- pricing/cost fields
- release/update metadata

Plan 3.8 should treat this source as best-effort and cacheable/fallible. Startup must remain usable if the endpoint is unavailable.

## Phase 1: Implement `ModelsDevMetadataSource`

### Changes

Replace the placeholder source with a real implementation:

```csharp
public sealed class ModelsDevMetadataSource : IModelMetadataSource
{
    public string Name => "models.dev";

    public ModelsDevMetadataSource(HttpClient? httpClient = null, Uri? endpoint = null);

    public ValueTask<IReadOnlyList<ModelMetadata>> LoadAsync(CancellationToken ct = default);
}
```

Recommended behavior:

- Default endpoint: `https://models.dev/api.json`.
- Use injected `HttpClient` for tests and host wiring.
- Fail closed on network, JSON, or schema errors: return `Array.Empty<ModelMetadata>()`.
- Propagate caller cancellation.
- Do not perform network work during construction.

### Mapping Rules

Map each provider/model record into `ModelMetadata`:

| models.dev field | Omicron field |
|------------------|---------------|
| provider key | `ProviderName` |
| model key / id | `ModelId` |
| `name` | `DisplayName` |
| `limit.context` | `ContextWindow` |
| `limit.output` | `MaxOutputTokens` |
| `tool_call` | `SupportsTools` |
| `reasoning` | `SupportsReasoning` |
| `attachment` or input image modality | `SupportsVision` |
| `structured_output` | `SupportsStructuredOutput` |
| pricing/cost input | `InputPricePerMillionTokens` |
| pricing/cost output | `OutputPricePerMillionTokens` |
| update timestamp if available | `LastUpdatedAt` |
| source | `Source = "models.dev"` |

Important:

- Preserve provider names from the response where possible.
- If model IDs are in `provider/model` format, normalize to the provider-local ID used by Omicron catalog entries where feasible.
- Null/unknown fields should remain `null`; do not invent values.

### Tests

Add tests using fake `HttpMessageHandler` / injected `HttpClient`:

- successful parse maps `limit.context` to `ContextWindow`;
- successful parse maps `limit.output` to `MaxOutputTokens`;
- capability booleans map correctly;
- malformed JSON returns empty;
- HTTP non-success returns empty;
- cancellation propagates.

## Phase 2: Catalog Metadata Refresh Wiring

### Changes

Add a convenient refresh path that layers:

1. `StaticModelMetadataSource`
2. `ModelsDevMetadataSource`

Options:

```csharp
public ValueTask<int> RefreshMetadataAsync(CancellationToken ct = default)
```

on `ModelCatalogService`, or a host-level method:

```csharp
public ValueTask<int> RefreshModelMetadataAsync(CancellationToken ct = default)
```

Preferred for frontend use: expose this through `OmicronHost` so CLI does not need to know source ordering.

Behavior:

- Best-effort.
- Preserve last-known-good metadata if all sources fail/empty.
- Propagate cancellation.
- Do not block basic startup if refresh fails.

### Tests

- Static + models.dev overlay overrides static context window.
- Empty/failing models.dev preserves static metadata.
- Host-level refresh populates catalog metadata.

## Phase 3: Frontend-Safe Metadata Access

### Problem

`ModelCatalogService.Metadata` exists, but `IModelCatalog` does not expose metadata. CLI currently receives `IModelCatalog`, so it cannot use metadata without downcasting.

### Changes

Add metadata access to `IModelCatalog` or add frontend-safe helper methods.

Preferred:

```csharp
public interface IModelCatalog
{
    IReadOnlyDictionary<string, Model> Models { get; }
    IReadOnlySet<string> FreeModelKeys { get; }
    bool IsFreeModel(string catalogKey);
    ModelMetadata? GetMetadata(Model model);
}
```

Alternatively:

```csharp
public static class ModelCatalogMetadataExtensions
{
    public static ModelMetadata? GetMetadata(this IModelCatalog catalog, Model model);
    public static int? GetEffectiveContextWindow(this IModelCatalog catalog, Model model);
    public static int? GetEffectiveMaxOutputTokens(this IModelCatalog catalog, Model model);
}
```

Effective values:

- Context: `metadata.ContextWindow ?? model.ContextWindow if > 0 else null`
- Max output: `metadata.MaxOutputTokens ?? model.MaxTokens if > 0 else null`

### Tests

- Metadata lookup is case-insensitive for provider/model keys.
- Effective context uses metadata when present.
- Effective context falls back to `Model.ContextWindow` when metadata absent.

## Phase 4: CLI Context Display

### `/model`

Update `ShowModel` to display metadata-backed values:

- Context window: effective metadata context first, fallback to model context.
- Max output tokens: effective metadata max output, if known.
- Optional: metadata source, e.g. `Metadata: models.dev`, for debugging.

Avoid showing `0` as a real context length. Use `unknown` if no value is known.

### `/models`

Add a compact context column to the list view.

Example:

```text
[ 1] * free GPT-4o Mini        openai       OpenAiChat        128k   openai:gpt-4o-mini
[ 2]       Claude Sonnet 4     anthropic    AnthropicMessages 200k   anthropic:claude-sonnet-4
```

Formatting helper:

```csharp
static string FormatTokenCountCompact(int? tokens)
```

Suggested output:

- `null` → `?`
- `< 1_000` → raw number
- thousands → `128k`
- millions → `1M`

### Refresh Timing

MVP options:

1. Refresh metadata during startup after catalog discovery, best-effort and non-fatal.
2. Or add a command later such as `/models-refresh`.

For Plan 3.8, prefer startup best-effort if it does not noticeably slow local startup. If network latency is concerning, use a short timeout or defer refresh behind an explicit command.

### Tests

Extract display helpers if needed and test:

- metadata context preferred over static context;
- fallback to static context;
- unknown display;
- compact formatting.
