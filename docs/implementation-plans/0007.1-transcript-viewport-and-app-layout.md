# Implementation Plan 0007.1: Transcript Viewport and App Layout

Status: Proposed
Target: Build app-owned scrollback, transcript virtualization, viewport state, and the widget layout system that makes the TUI usable for real agent sessions.

## Purpose

Plan 7 built the terminal backend, frame buffer, and diff renderer. Plan 7.1 adds the application layer: transcript blocks, layout caching, viewport scrolling with non-yanking follow-tail, and a compact widget layout system. This turns the raw rendering stack into a usable agent interface.

## Primary RFCs

- RFC 0004 — Transcript Viewport, Scrollback, Layout, and Input
- RFC 0002 — UI Abstractions, Plugins, Commands, and Permissions (block model)
- RFC 0009 — Implementation Roadmap (Phase Set 1c, 2a)

## Reference Analysis

`docs/reports/0001-tui-renderer-codebase-analysis.md` — key adoptions:

- **Measure/Arrange layout protocol** — adopted from Termina's `ILayoutNode.Measure(available) → Size` + `Arrange(bounds)` + `Render(context)`.
- **Streaming text model** — Termina's `StreamingTextNode` for real-time LLM output. Uses `PersistedStreamBuffer` / `WindowedStreamBuffer` for scrollback.
- **Reactive invalidation** — Termina's `IInvalidatingNode.Invalidated` (R3 `Observable<Unit>`) or simpler `MarkDirty()` pattern. Only dirty nodes re-render.

## Depends On

- Plan 7 (`Utf8TextStore`, `TerminalFrame`, `DifferentialRenderer`, `TuiShell`, `ITerminalBackend`)
- Plan 5 (`ContentBlock` model)
- Plan 3.1 (`TextLineSplitter`)

## Non-Goals

- No markdown parser (Plan 8)
- No syntax highlighting (Plan 8)
- No virtual terminal emulator panes (Plan 11)
- No command palette or rich keybindings beyond basic navigation
- No plugin panel hosting
- No multi-agent dashboard
- No session replay / resume UI (backend exists from Plan 3.5)

## Guiding Principles

1. **App-owned scrollback.** The TUI owns transcript history, not the host terminal.
2. **Render only visible wrapped rows.** Do not rewrap the entire transcript on every token.
3. **Follow-tail by default; intentional scroll stops follow.**
4. **Resize is an invalidation event, not a reparse.** Rebuild layout caches, not semantic blocks.
5. **Keep layout simple.** Rects, stacks, splits, and fixed/flex sizing are enough.

## Phase A: Transcript Block Model Integration

### Goals
Bridge `ContentBlock` (Plan 5) and `OmicronEvent` into `TranscriptBlock` records that carry byte ranges into the `Utf8TextStore`.

### Deliverables

#### A1. `TranscriptBlock` records
```csharp
namespace Omicron.Core.Rendering.Transcript;

public abstract record TranscriptBlock(BlockId Id);

public sealed record UserMessageBlock(
    BlockId Id,
    TextPosition Position,
    int ByteLength,
    IReadOnlyList<ContentBlock> Content) : TranscriptBlock(Id);

public sealed record AssistantMessageBlock(
    BlockId Id,
    TextPosition Position,
    int ByteLength,
    IReadOnlyList<ContentBlock> Content,
    bool IsStreaming) : TranscriptBlock(Id);

public sealed record ToolCallBlock(
    BlockId Id,
    TextPosition Position,
    int ByteLength,
    string ToolName,
    ToolCallState State,
    IReadOnlyList<ContentBlock> Output) : TranscriptBlock(Id);

public sealed record SystemNoticeBlock(
    BlockId Id,
    TextPosition Position,
    int ByteLength,
    UiNotification Notification) : TranscriptBlock(Id);

public enum ToolCallState { Pending, Running, Completed, Failed }
```

- `Position` points into a shared `Utf8TextStore`.
- `ByteLength` covers the raw text bytes for this block.
- `Content` carries semantic blocks (plain text, markdown, code, diff, etc.) from Plan 5.

#### A2. `BlockId`
```csharp
namespace Omicron.Core.Rendering.Transcript;

public readonly record struct BlockId(long Value)
{
    private static long _next = 1;
    public static BlockId New() => new(Interlocked.Increment(ref _next));
}
```

#### A3. `TranscriptStore`
```csharp
namespace Omicron.Core.Rendering.Transcript;

public sealed class TranscriptStore
{
    public Utf8TextStore Text { get; } = new();
    public IReadOnlyList<TranscriptBlock> Blocks => _blocks;

    /// <summary>Append assistant text delta and return the updated block.</summary>
    public AssistantMessageBlock AppendAssistantDelta(BlockId blockId, ReadOnlySpan<byte> utf8Delta);

    /// <summary>Start a new user message block.</summary>
    public UserMessageBlock AppendUserMessage(IReadOnlyList<ContentBlock> content);

    /// <summary>Start or update a tool call block.</summary>
    public ToolCallBlock AppendToolCall(string toolName, ToolCallState state, IReadOnlyList<ContentBlock> output);

    /// <summary>Finalize the last assistant block (mark IsStreaming = false).</summary>
    public void CompleteLastAssistantBlock();

    /// <summary>Truncate / reset for session reset.</summary>
    public void Clear();
}
```

- `AppendAssistantDelta` appends bytes to `Utf8TextStore`, extends the last `AssistantMessageBlock`, and returns it.
- If the last block is not an assistant block or is already completed, start a new one.

## Phase B: Layout Cache

### Goals
Build a width-dependent layout cache that maps transcript blocks into wrapped terminal rows. Rebuild only invalidated blocks.

### Deliverables

#### B1. `WrappedLineInfo`
```csharp
namespace Omicron.Core.Rendering.Transcript;

public readonly record struct WrappedLineInfo(
    BlockId BlockId,
    long ByteStart,      // offset into Utf8TextStore
    int ByteLength,
    int CellStart,       // cell offset within the row
    int CellWidth,       // cells occupied by this line
    bool IsContinuation, // true if this is a wrapped continuation of a longer line
    int LogicalLineIndex // which logical line inside the block this is
);
```

#### B2. `TranscriptLayoutCache`
```csharp
namespace Omicron.Core.Rendering.Transcript;

public sealed class TranscriptLayoutCache
{
    public int TerminalWidth { get; private set; }
    public int TotalWrappedRows { get; private set; }

    public void ReflowForWidth(int terminalWidth, TranscriptStore store);
    public void InvalidateBlock(BlockId blockId);
    public void InvalidateFrom(BlockId blockId);
    public IReadOnlyList<WrappedLineInfo> GetVisibleLines(int firstWrappedRow, int height);
}
```

Reflow algorithm:
1. Iterate all blocks in order.
2. For each block, read its UTF-8 bytes from `Utf8TextStore`.
3. Split into logical lines using `TextLineSplitter`.
4. For each logical line, wrap into `TerminalWidth` columns using `CellWidthCalculator`.
5. Emit `WrappedLineInfo` per wrapped row.
6. Cache the list per block so re-layout of an unchanged block is O(1).

Incremental behavior:
- `InvalidateBlock` clears the cached wrapped lines for that block only.
- `InvalidateFrom` clears that block and all subsequent blocks (needed when a block byte offset shifts).
- Appending a delta to the last assistant block only invalidates that block.

### Tests
- `LayoutCache_SingleLine_FitsWidth_OneWrappedLine`
- `LayoutCache_LongLine_WrapsCorrectly`
- `LayoutCache_Cjk_WrapsAtDoubleWidthBoundary`
- `LayoutCache_Emoji_WrapsAtDoubleWidthBoundary`
- `LayoutCache_Resize_ChangesWrappedRows`
- `LayoutCache_InvalidateBlock_OnlyRebuildsThatBlock`
- `LayoutCache_InvalidateFrom_RebuildsSubsequentBlocks`
- `LayoutCache_GetVisibleLines_ReturnsCorrectWindow`

### Acceptance Criteria
- Wrapping respects `CellWidthCalculator` (CJK/emoji = 2 cells).
- Resize reflows all blocks and updates `TotalWrappedRows`.
- Invalidate only rebuilds affected blocks.
- Performance: reflow 10k lines in <50 ms.

## Phase C: Viewport State

### Goals
Manage scroll position, follow-tail behavior, and new-line indicators.

### Deliverables

#### C1. `ViewportState`
```csharp
namespace Omicron.Core.Rendering.Transcript;

public sealed class ViewportState
{
    public int FirstVisibleWrappedRow { get; set; }
    public bool FollowTail { get; set; } = true;
    public int UnseenLineCount { get; private set; }

    public void OnContentAppended(int newTotalWrappedRows);
    public void ScrollUp(int rows);
    public void ScrollDown(int rows);
    public void ScrollToTop();
    public void ScrollToBottom(int totalWrappedRows);
    public void MarkSeen();
}
```

Behavior:
- `OnContentAppended`: if `FollowTail`, set `FirstVisibleWrappedRow` so bottom is visible. If not, increment `UnseenLineCount`.
- `ScrollUp` / `ScrollDown`: set `FollowTail = false`, adjust row.
- `ScrollToBottom`: set `FollowTail = true`, `UnseenLineCount = 0`.

#### C2. New-line indicator rendering
When `UnseenLineCount > 0` and `FollowTail == false`, render a small indicator at the bottom-right of the transcript area:
```text
"↓ 14 new"
```
This is drawn by the `TranscriptViewportWidget` after the main transcript rows.

### Tests
- `ViewportState_FollowTail_AutoScrollsToBottomOnAppend`
- `ViewportState_ScrolledUp_DoesNotYankOnAppend`
- `ViewportState_ScrolledUp_TracksUnseenLines`
- `ViewportState_ScrollDown_ReachesBottom_ResumesFollowTail`

### Acceptance Criteria
- New output does not steal scroll focus when user intentionally scrolled up.
- Unseen-line indicator appears and clears on scroll-to-bottom.
- Follow-tail resumes when user scrolls to the bottom.

## Phase D: Widget Layout System

### Goals
A minimal layout system for the TUI app. Not a general-purpose UI toolkit—just enough for transcript + status + input.

### Deliverables

```csharp

public readonly record struct Rect(int X, int Y, int Width, int Height)
{
    public bool Contains(int x, int y) => x >= X && x < X + Width && y >= Y && y < Y + Height;

```

#### D2. `ITuiWidget`

## Phase E: TUI Widgets

### Goals
Build the three main widgets and wire them into `TuiShell`.

### Deliverables

#### E1. `TranscriptViewportWidget`
```csharp
namespace Omicron.CLI.Tui;

public sealed class TranscriptViewportWidget : ITuiWidget
{
    private readonly TranscriptStore _store;
    private readonly TranscriptLayoutCache _layout;
    private readonly ViewportState _viewport;

    public void UpdateFromEvent(OmicronEvent evt); // adapts events into store updates
    public void ScrollUp(int rows) => _viewport.ScrollUp(rows);
    public void ScrollDown(int rows) => _viewport.ScrollDown(rows);
    public void ScrollToTop() => _viewport.ScrollToTop();
    public void ScrollToBottom() => _viewport.ScrollToBottom(_layout.TotalWrappedRows);

    public Size Measure(Size available) => available;
    public void Arrange(Rect bounds) { /* store bounds */ }
    public void Render(RenderContext ctx);
}
```

Render loop:
1. Get visible wrapped lines from `LayoutCache` using `ViewportState.FirstVisibleWrappedRow` and `bounds.Height`.
2. For each `WrappedLineInfo`, read the UTF-8 bytes from `Utf8TextStore.Slice`.
3. Decode and draw into the `TerminalFrame` at the correct row/column.
4. If `ViewportState.UnseenLineCount > 0`, draw the indicator at the bottom-right.

Streaming integration:
- `UpdateFromEvent` handles:
  - `AssistantTextDeltaEvent` → `store.AppendAssistantDelta`
  - `UserMessageEvent` → `store.AppendUserMessage`
  - `ToolInvocationStartedEvent` / `ToolInvocationCompletedEvent` → `store.AppendToolCall`
  - `SessionResetEvent` → `store.Clear`
- After each update, call `_layout.InvalidateBlock` or `InvalidateFrom`.

#### E2. `StatusBarWidget`
Renders a single row with three sections:
- Left: current model name
- Center: provider / API type
- Right: token usage or session event count

Data source: subscribe to `IEventSink` or read from `AgentSession` state.

#### E3. `InputEditorWidget`
Wrap the existing `LineEditor` (from Plan 3.6) into a widget:
- Render the input buffer into the widget bounds.
- Show cursor at the correct column.
- Support multi-line if `LineEditor` already does; otherwise single-line.
- `Enter` submits; `Shift+Enter` inserts newline.
- `Escape` cancels current input.

#### E4. `AppLayout`
Factory that builds the layout tree and wires event handlers:
```csharp
namespace Omicron.CLI.Tui;

public sealed class AppLayout : IDisposable
{
    public AppLayout(AgentSession session, ITerminalBackend backend, IEventSink eventSink);
    public async Task RunAsync(CancellationToken ct);
}
```

`RunAsync`:
1. Build layout tree.
2. Subscribe to session events and update `TranscriptViewportWidget`.
3. Read terminal events:
   - `PageUp` / `PageDown` → scroll transcript
   - `Home` / `End` → top / bottom
   - `Ctrl+C` → cancel operation
   - `Ctrl+D` → exit
   - `Enter` → submit input
   - Character keys → route to `InputEditorWidget`
4. Request render after each event or session update.
5. Render loop: measure → arrange → render to frame → diff → output.

- `TranscriptViewportWidget_UpdateFromEvent_AppendsAssistantDelta`

### Acceptance Criteria
- Transcript viewport renders plain text from `TranscriptStore`.
- PageUp/PageDown scrolls by viewport height.
- Home/End jumps to top/bottom.
- Streaming assistant output appends to the bottom and auto-scrolls when follow-tail is on.
- Scrolling up stops follow-tail and shows a new-line indicator when more output arrives.
- Status bar shows current model.
- Input editor accepts typing and submits on Enter.
- Terminal is restored on exit.

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Layout cache invalidation is buggy | Extensive tests for partial invalidation; use immutable block IDs. |
| Follow-tail logic races with scroll | Atomic viewport state updates; render loop reads consistent snapshot. |
| Multi-byte UTF-8 splits across wrapped lines | Always break at grapheme boundaries; never split inside a UTF-8 sequence. |
| Wide characters split across row boundary | If a wide char doesn't fit at end of row, wrap it to next row entirely. |
| Widget measure/arrange is slow | Keep it simple; no recursive deep trees for MVP. |

## Definition of Done

- `TranscriptStore` maintains blocks over `Utf8TextStore` with correct byte ranges.
- `TranscriptLayoutCache` produces wrapped rows for all blocks and supports incremental invalidation.
- `ViewportState` manages follow-tail, scroll position, and unseen-line indicators.
- Widget layout system supports flex and fixed sizing with clipping.
- `TranscriptViewportWidget`, `StatusBarWidget`, and `InputEditorWidget` render into `TerminalFrame`.
- `AppLayout` runs a full event/render loop with keyboard navigation.
- Existing `--tui` CLI mode is usable for real chat sessions.
- All tests pass with 0 warnings.
