# Implementation Plan 0003.25: Workspace Transaction Manager Integration

Status: Complete  
Depends on: Plan 3 Phase 4 workspace transactions/diffs  
Primary RFCs: RFC 0006, RFC 0012

## Purpose

Expose workspace transactions through the host composition root so future tools and services do not directly construct `WorkspaceTransaction` or depend on `HostWorkspaceFileSystem` concretes.

This is a small bridge plan before session UX and transaction-backed edit tools.

## Goals

- Add a stable transaction creation entry point.
- Keep transaction internals behind interfaces.
- Avoid audit/session event semantics until transaction ownership is clear.

## Deliverables

Add:

```csharp
public interface IWorkspaceTransactionManager
{
    IWorkspaceTransaction BeginTransaction();
}

public sealed class WorkspaceTransactionManager : IWorkspaceTransactionManager
{
    public IWorkspaceTransaction BeginTransaction();
}
```

Wire into `OmicronHost`:

```csharp
public IWorkspaceTransactionManager WorkspaceTransactions { get; }
```

Constructor should use the existing host-backed `HostWorkspaceFileSystem`.

## Acceptance Criteria

- `OmicronHost.WorkspaceTransactions.BeginTransaction()` returns a working transaction.
- Transaction overlay `Files` works through the manager-created transaction.
- Existing transaction tests still pass.
- Add host integration test proving manager wiring.
- No audit events are emitted yet.
- Build/test pass with no warnings.
