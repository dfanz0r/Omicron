Status: **Draft / Ready for implementation**

## Purpose

Before entering Plan 4 (transaction-backed edit harness), address the backlog items rated **high** and **medium** priority from the comprehensive Plan 3 review. These are not new features — they are reliability, observability, and test-coverage improvements that reduce the risk of building the edit harness on a shaky foundation.

Goals:

1. **Transaction reliability** — transactions must be observable (events) and recoverable (atomicity or rollback tracking).
2. **Event sink async safety** — remove sync-over-async hazards before background workers or async UI consume the sink.
3. **Session config immutability** — prevent config drift that would corrupt edit-harness snapshots.
4. **JSONL durability hardening** — concurrency safety and automatic round-trip validation for new event types.
5. **CLI input reliability** — test the primary user input path and remove ambiguous session matching footguns.

Non-goals:

- No new provider APIs or model shapes.
- No new TUI/GUI/rendering work.
- No plugin or WASM infrastructure.

## Current State Summary

| Subsystem | State | Why It Needs Hardening |
|-----------|-------|----------------------|
| `WorkspaceTransaction` | Staging + overlay VFS works; commit is sequential best-effort | Plan 4 edit harness needs atomic multi-file edits or explicit recovery |
| `IEventSink` | Sync-only; `PersistentEventSink` uses `.GetAwaiter().GetResult()` | Plan 4 may add async command handlers or background workers |
| `AgentSession` | Config properties (`Model`, `ApiKey`, `MaxTokens`, etc.) are mutable post-construction | Edit harness snapshots may capture inconsistent state |
| `JsonlSessionStore` | Single-threaded append works; no concurrent stress coverage | Event volume will grow with transaction audit events |
| `OmicronEvent` deserialization | Manual `$type` switch in `JsonlSessionStore` | New transaction events (FH-0018) must not be silently dropped on replay |
| `SlashCommandDispatcher` | Prefix matching uses first match; no ambiguity detection | Session resume/fork UX will be used more as session count grows |
| `LineEditor` | Complex raw-keyboard logic; zero test coverage | Primary user input path has no regression protection |

## Phases

### Phase 1: Event System Hardening (FH-0015 + FH-0018)

**Goal:** Make the event sink safe for async callers, and add transaction lifecycle events so Plan 4 can observe edit operations.

#### 1a. Add `EmitAsync`/`EmitBatchAsync` to `IEventSink` (FH-0015)

- Add `ValueTask<OmicronEvent> EmitAsync(OmicronEvent evt, CancellationToken ct)` to `IEventSink`.
- Add `ValueTask<IReadOnlyList<OmicronEvent>> EmitBatchAsync(IReadOnlyList<OmicronEvent> events, CancellationToken ct)` to `IEventSink`.
- Implement in `InMemoryEventSink` — trivial (already in-memory and synchronous under the hood).
- Implement in `PersistentEventSink` — call `_store.AppendEventsAsync` directly without `.GetAwaiter().GetResult()`.
- Keep the sync `Emit`/`EmitBatch` as convenience wrappers that call the async versions with `.GetAwaiter().GetResult()`, but mark them with a documentation comment warning about the sync-over-async hazard.
- Update `SessionEventWriter` to expose `EmitAsync<T>` and `Envelope()` remains sync (it just creates a stamp-ready envelope).
- **Test:** Add `PersistentEventSink` async tests verifying that `EmitAsync` does not block and that events are persisted in order.

#### 1b. Add transaction lifecycle events (FH-0018)

Add the following event types to `OmicronEvent.cs`:

```csharp
public sealed record TransactionStartedEvent(
    EventEnvelope Envelope,
    WorkspaceTransactionId TransactionId) : OmicronEvent(Envelope);

public sealed record TransactionStagedEvent(
    EventEnvelope Envelope,
    WorkspaceTransactionId TransactionId,
    string Path,
    string Action) : OmicronEvent(Envelope); // Action: "write", "delete", "move"

public sealed record TransactionCommittedEvent(
    EventEnvelope Envelope,
    WorkspaceTransactionId TransactionId) : OmicronEvent(Envelope);

public sealed record TransactionRolledBackEvent(
    EventEnvelope Envelope,
    WorkspaceTransactionId TransactionId) : OmicronEvent(Envelope);
```

- Wire an optional `IEventSink` into `WorkspaceTransaction` constructor.
- Emit `TransactionStartedEvent` on first stage operation (lazy — don't emit until something is actually staged).
- Emit `TransactionStagedEvent` on each `StageWrite`, `StageDelete`, `StageMove`.
- Emit `TransactionCommittedEvent` on successful `CommitAsync`.
- Emit `TransactionRolledBackEvent` on `RollbackAsync` or `DisposeAsync` without commit.
- Update `JsonlSessionStore.DeserializeEvent` switch to handle the new types.
- **Test:** Add `WorkspaceTransaction` event emission tests verifying that staging, commit, and rollback all emit the correct events with proper sequencing.

**Completion criteria:**
- [ ] `IEventSink` has async overloads implemented by both sinks.
- [ ] `PersistentEventSink` async path avoids sync-over-async.
- [ ] New transaction events exist in `OmicronEvent.cs`.
- [ ] `WorkspaceTransaction` emits lifecycle events when an `IEventSink` is provided.
- [ ] All new event types round-trip through `JsonlSessionStore`.
- [ ] Tests pass (346 + new tests).

### Phase 2: Transaction Reliability (FH-0019 + FH-0023)

**Goal:** Make multi-file commit either atomic or explicitly recoverable, and test the failure path.

#### 2a. Atomic commit or rollback tracking (FH-0019)

Approach: **Two-phase commit with temp files + rename** (MVP-appropriate, no external dependencies).

- Add a private helper `CommitWithRollbackTrackingAsync`.
- Phase 1 — preflight:
  - Validate all staged operations (e.g., ensure move sources exist, write targets are within root).
  - If any preflight fails, throw before mutating the host.
- Phase 2 — apply with temp files:
  - For each `StageWrite`: write to `{host-path}.omicron-tx-{txId}.tmp`.
  - For each `StageDelete`: rename original to `{host-path}.omicron-tx-{txId}.deleted`.
  - For each `StageMove`: copy source to `{dest-path}.omicron-tx-{txId}.tmp`, rename source to `{source-path}.omicron-tx-{txId}.moved`.
  - Track all temp files in a `List<string>`.
- Phase 3 — finalize:
  - Rename all `.tmp` files to their final names.
  - Delete all `.deleted` and `.moved` backups.
- On failure during Phase 2 or 3:
  - Walk the tracked temp/backups and restore originals (rename `.moved` back, delete `.tmp`, restore `.deleted`).
  - Throw `InvalidOperationException` with a message indicating partial rollback status.
- On success: clean up any orphaned `.omicron-tx-*` files (defensive).
- Document in XML docs that commit is now atomic-at-rename-level, not fsync-guaranteed.

Alternative (simpler): If temp-file complexity is too high for this plan, implement **operation journaling** instead:
- Track a `List<CommittedOperation>` as each host operation succeeds.
- On failure, attempt to reverse each committed operation in reverse order.
- Document that rollback is best-effort and may fail if reverse operations throw.

**Decision:** Use the simpler journaling approach for this plan. The temp-file approach is better but can be deferred to FH-0019-followup if it risks destabilizing the MVP.

#### 2b. Commit failure recovery test (FH-0023)

- Create a `ThrowingFileSystem` test double that wraps `HostWorkspaceFileSystem` and throws on the Nth write/delete/move.
- Test that `CommitAsync` throws and leaves the host in its original state when a failure occurs at various points (first operation, middle operation, last operation).
- Test that `TransactionRolledBackEvent` is emitted when rollback occurs.
- **Test location:** `Omicron.Core.Tests/WorkspaceTransactionTests.cs`.

**Completion criteria:**
- [ ] `WorkspaceTransaction.CommitAsync` either commits fully or rolls back to pre-commit state.
- [ ] Failure path is tested with a mock filesystem.
- [ ] Transaction events correctly reflect commit vs rollback.
- [ ] Tests pass.

### Phase 4: JSONL Hardening (FH-0003 + FH-0001 + FH-0022)

**Goal:** Make JSONL event serialization maintainable and safe under concurrent writes.

#### 4a. Event type registry for deserialization (FH-0003)

- Create `OmicronEventRegistry`:

```csharp
public static class OmicronEventRegistry
{
    private static readonly Dictionary<string, Type> _types = new(StringComparer.OrdinalIgnoreCase);
    private static readonly Dictionary<Type, string> _names = new();

    static OmicronEventRegistry()
    {
        Register<SessionStartedEvent>();
        Register<SessionResetEvent>();
        // ... all concrete OmicronEvent types
    }

    private static void Register<T>() where T : OmicronEvent
    {
        var name = typeof(T).Name;
        _types[name] = typeof(T);
        _names[typeof(T)] = name;
    }

    public static Type? GetType(string typeName) => _types.GetValueOrDefault(typeName);
    public static string GetName(Type type) => _names[type];
    public static IReadOnlyCollection<Type> AllTypes => _types.Values;
}
```

- Replace the manual switch in `JsonlSessionStore.DeserializeEvent` with a registry lookup:
  ```csharp
  var type = OmicronEventRegistry.GetType(typeName);
  if (type is not null)
      return (OmicronEvent?)JsonSerializer.Deserialize(line, type, _eventJsonOptions);
  ```
- Add a test that enumerates `OmicronEventRegistry.AllTypes` and verifies every type round-trips through `JsonlSessionStore`.
- **This guarantees that FH-0018's new transaction events cannot be silently missed** — the registry test will fail if a new event type is added without registration.

#### 4b. Per-session file locking for concurrency (FH-0001)

- Add a `ConcurrentDictionary<SessionId, SemaphoreSlim>` to `JsonlSessionStore` for per-session write serialization.
- In `AppendEventsAsync`, acquire the semaphore for the target session before opening the file stream.
- Release in a `finally` block.
- This does not solve cross-process concurrency, but it eliminates in-process races for the same session file.

#### 4c. Concurrent access stress test (FH-0022)

- Add `JsonlSessionStoreConcurrencyTests`:
  - Create a store in a temp directory.
  - Create one session.
  - Fire 10 tasks, each appending 100 events to the same session.
  - Read back all events and verify:
    - Total count = 1000.
    - Sequence numbers are strictly monotonic.
    - No duplicate or missing events.
    - File is not corrupt (all lines deserialize successfully).

**Completion criteria:**
- [ ] `OmicronEventRegistry` exists and replaces manual deserialization switch.
- [ ] Registry test verifies round-trip for all known event types.
- [ ] `JsonlSessionStore` uses per-session locking.
- [ ] Stress test passes with 1000 concurrent appends.
- [ ] Tests pass.

### Phase 5: CLI Hardening (FH-0010 + FH-0021)

**Goal:** Remove ambiguous session matching footguns and add regression tests for the primary input path.

#### 5a. Ambiguous prefix detection (FH-0010)

- In `SlashCommandDispatcher.ResumeSession` and `ForkSession`, when matching by prefix:
  - Find **all** sessions whose ID starts with the given prefix.
  - If more than one matches, print all candidates with their indices and short IDs, then return `Continue` (do not resume/fork).
  - If zero match, print "No session matching '{prefix}'".
  - If exactly one matches, proceed as before.
- Same logic for both `/resume` and `/fork`.

#### 5b. `LineEditor` tests (FH-0021)

- Extract `LineEditor` logic into a testable core:
  - Create `LineEditorState` that holds the buffer, cursor position, and paste mode.
  - Create `LineEditorEngine` with methods like `ProcessKey(KeyInfo key, LineEditorState state)` that mutate the state.
  - `LineEditor.ReadLine()` becomes a thin wrapper that reads `ConsoleKeyInfo`, maps to `KeyInfo`, and delegates to the engine.
- Add tests for:
  - Typing "hello" produces buffer "hello".
  - Backspace removes last character.
  - Left arrow moves cursor.
  - Enter submits.
  - Shift+Enter inserts newline.
  - Escape clears buffer.
  - Tab completion replaces buffer when single match.
  - Tab completion with multiple matches does not modify buffer.
  - Paste detection (multiple keys queued) treats Enter as literal newline.
- **Test location:** `Omicron.Core.Tests/LineEditorTests.cs` (or `Omicron.CLI.Tests/` if CLI gets its own test project).

**Completion criteria:**
- [ ] `/resume` and `/fork` detect and report ambiguous prefix matches.
- [ ] `LineEditor` core logic is extracted into a testable state machine.
- [ ] LineEditor tests cover typing, navigation, backspace, enter, shift+enter, escape, and tab completion.
- [ ] Tests pass.
