# Implementation Plan 0003.5: Session Resume and Fork UX

Status: Proposed  
Depends on: Plan 3 Phase 1/2 persistence and projection  
Primary RFCs: RFC 0001, RFC 0006

## Purpose

Make the default disk persistence useful from the CLI by allowing users to list, resume, and fork saved sessions.

## Goals

- Add practical CLI session navigation.
- Hydrate runtime state from persisted events through `SessionProjection`.
- Support cross-model movement by transcript replay/forking, not provider-state continuation.

## Commands

```text
/sessions [n]
/resume <session-id-prefix|index>
/fork <session-id-prefix|index> [--model <model-key|n>]
```

Optional later:

```text
/session <id>
/session-info <id>
```

## Runtime Semantics

### Resume

- Reads events from `ISessionStore`.
- Projects with `SessionProjector`.
- Creates a new active `AgentSession` for the same persisted session if supported.
- Restores transcript messages from projection.
- Restores provider state only if same provider/model/API shape and storage policy is safe.

### Fork

- Creates a new `SessionRecord`.
- Replays projected transcript into the new session.
- Clears provider-managed continuation state by default.
- Allows model/provider change.
- Future: emit explicit fork lineage event/metadata.

## Required Core Work

Add an `AgentSession` hydration path, likely one of:

```csharp
AgentSession.FromProjection(...)
```

or constructor/factory support for initial messages/provider state.

Avoid mutating an existing `AgentSession.Model` mid-session. Model switch still creates a new session object.

## CLI Work

- Extend `SlashCommandDispatcher`.
- Display session list with:
  - short id;
  - created/updated timestamps;
  - provider/model;
  - status;
  - event count if cheap.
- Allow index selection matching `/model` style.
- Update `/status` to show current session id and persistence path.

## Acceptance Criteria

- `/sessions` lists persisted sessions from disk-backed store.
- `/resume <id>` restores enough transcript to continue the conversation.
- `/fork <id> --model <model>` creates a new session with replayed transcript and no unsafe provider continuation state.
- Same-model resume preserves safe provider state where currently supported.
- Cross-model fork clears provider state.
- Tests cover projection-to-session hydration, resume, fork, and cross-model provider-state clearing.
- CLI still starts with default disk persistence.
- Build/test pass with no warnings.

## Non-Goals

- No provider-state transfer across different providers/models.
- No UI beyond CLI slash commands.
- No session summaries/titles unless trivial.
- No full branch graph UI.
