# Implementation Plan 0002.5: CLI Slash Commands and Day-to-Day Usability

Status: In progress  
Target: improve the MVP CLI without changing the core provider architecture.

## Purpose

The CLI currently works, but day-to-day use is awkward:

- model switching requires leaving chat with `exit` and returning to the model picker;
- `reset` is a special bare word rather than a consistent command;
- there is no quick way to inspect current model/provider/API state;
- provider-state/debug information is invisible;
- available tools are not discoverable during chat.

This plan adds slash commands as a focused CLI usability layer while preserving the Plan 1.5/2 architecture.

## Goals

1. Add slash commands in chat mode.
2. Keep command parsing out of the provider/model path.
3. Do not introduce a second agent/session loop.
4. Keep `AgentSession` as the runtime owner of conversation state.
5. Make model/provider/API/debug state visible enough to test Responses work.
6. Prepare the CLI to use the existing core command registry later without overbuilding now.

## Non-Goals

- Do not build a full TUI.
- Do not implement plugin commands or WASM command execution.
- Do not add persistence or transcript replay.
- Do not change provider request/response semantics.
- Do not add complex shell-like parsing; simple command + args is enough.

## Current CLI Shape

Relevant file:

```text
Omicron.CLI/Program.cs
```

Current flow:

1. Create `OmicronHost`.
2. Load config and model catalog.
3. Show model picker.
4. Create one `AgentSession` for selected model.
5. Enter `ChatLoop(session)`.
6. Inside chat:
   - bare `exit` returns to model picker;
   - bare `reset` clears the current session;
   - all other input is sent to `session.PromptAsync(...)`.

## Desired Command UX

Commands should be prefixed with `/`.

Initial commands:

```text
/help                 Show available slash commands
/model                Show current model/provider/API type
/status               Show current session/model/config/provider-state summary
/tools                List registered tools
/events [n]           Show recent session events, default 20
/provider-state       Show provider state for current session/model
/clear-state          Clear provider state for current session/model only
/reset                Reset current conversation and provider state
/exit                 Exit current chat session back to model picker
/quit                 Quit the app
```

Second-pass commands:

```text
/models               Show model list from inside chat
/switch [number]      Switch model without returning through bare exit flow
/config               Open config menu
/refresh              Re-fetch model catalog
/api                  Show endpoint/API routing details for current model
```

Compatibility aliases:

```text
exit                  Keep as alias for /exit for now
reset                 Keep as alias for /reset for now
?                     Alias for /help
```

## Proposed Design

### 1. Introduce command result type in CLI project

Add a small CLI-only command result type. Keep it local to `Omicron.CLI` for now.

```csharp
internal enum ChatCommandAction
{
    Continue,
    ExitSession,
    ExitApp,
    ResetSession,
    ClearProviderState,
    SwitchModel,
    ShowConfig,
    RefreshModels
}

internal sealed record ChatCommandResult(
    ChatCommandAction Action = ChatCommandAction.Continue,
    string? Message = null,
    string? Argument = null);
```

For the first pass, only `Continue`, `ExitSession`, `ExitApp`, `ResetSession`, and `ClearProviderState` need to be active.

### 2. Add a command parser/dispatcher helper

Either keep as local functions in `Program.cs` initially or add:

```text
Omicron.CLI/SlashCommandDispatcher.cs
```

Preferred: add a separate file to keep `Program.cs` from growing further.

Candidate shape:

```csharp
internal sealed class SlashCommandDispatcher
{
    public bool IsCommand(string input);

    public ChatCommandResult Execute(
        string input,
        SlashCommandContext context);
}
```

Context:

```csharp
internal sealed record SlashCommandContext(
    OmicronHost Host,
    AgentSession Session,
    Model Model,
    string ModelKey,
    AgentConfig Config,
    IModelCatalog Catalog);
```

Keep output either:

- directly printed by handlers for simplicity; or
- returned as strings for testing.

Recommendation: return strings for easy tests where practical, but allow `Program.cs` to handle display formatting.

### 3. Update `ChatLoop` to route slash commands

Current special cases:

```csharp
if (input.Equals("exit", ...)) break;
if (input.Equals("reset", ...)) { session.Reset(); ... }
```

Replace with:

```csharp
if (slashDispatcher.IsCommand(input))
{
    var result = slashDispatcher.Execute(input, context);
    switch (result.Action)
    {
        case ChatCommandAction.Continue:
            continue;
        case ChatCommandAction.ResetSession:
            session.Reset();
            Console.WriteLine("(Conversation reset)");
            continue;
        case ChatCommandAction.ClearProviderState:
            host.ProviderStateManager.Clear(key, reason: "slash_command");
            continue;
        case ChatCommandAction.ExitSession:
            return ChatLoopResult.ExitSession;
        case ChatCommandAction.ExitApp:
            return ChatLoopResult.ExitApp;
    }
}
```

This likely requires `ChatLoop` to return a result instead of `Task`:

```csharp
internal enum ChatLoopResult
{
    ExitSession,
    ExitApp
}
```

The outer loop can then exit the app if needed.

### 4. Provider-state command behavior

For current model/session, construct the same key as `AgentSession`:

```csharp
var key = ProviderStateKey.Create(
    session.Id,
    session.AgentId,
    model.ProviderName,
    model.Id,
    model.ApiType);
```

`/provider-state` prints:

```text
Provider state:
  key: openrouter / openai/gpt-5.4-mini / OpenAiResponses
  previous_response_id: <none>
  conversation_id: <none>
  session_affinity: <none>
  storage_policy: PreferStateless
```

For OpenRouter Responses, this should usually show no previous response ID because we default to stateless.

`/clear-state` clears only this key, not the whole session:

```csharp
host.ProviderStateManager.Clear(key, reason: "slash_command_clear_state");
```

`/reset` still calls `session.Reset()`, which clears messages and all provider state for the session.

### 5. Events command behavior

`/events [n]` reads from the authoritative sink/event log:

```csharp
var events = host.EventLog.GetSessionEvents(session.Id).TakeLast(n);
```

Print compact rows:

```text
#12 UserMessageEvent
#13 TurnStartedEvent
#14 ToolInvocationStartedEvent read_path
#15 ToolInvocationCompletedEvent read_path ok
#16 AssistantResponseCompleteEvent 1079↑ 238↓
```

This command is useful because nested service events are sink-only and not yielded from `PromptAsync()`.

### 6. Status command behavior

`/status` should print:

```text
Session: <session id>
Agent: <agent id>
Model: OpenAI: GPT-5.4 Mini (OR)
Provider: openrouter
API: OpenAiResponses
Storage policy: PreferStateless
Supports previous_response_id: false
Tools: 4 registered
Messages: 7
Events: 18
```

This helps validate Plan 2 runtime decisions.

### 7. Switch/model commands second pass

`/switch` is slightly more invasive because `ChatLoop` currently owns exactly one `AgentSession`.

Recommended second-pass flow:

- `/models` prints visible model list using the same filtering/sorting as main menu.
- `/switch 12` returns `ChatCommandAction.SwitchModel` with selected model key.
- Outer loop creates a new `AgentSession` and re-enters chat.

Do **not** mutate `AgentSession.Model` mid-session for now. New model = new session. This avoids accidental cross-model provider-state continuation.

Possible result:

```csharp
internal sealed record ChatLoopResult(
    ChatLoopExitReason Reason,
    string? SwitchToModelKey = null);
```

Reasons:

```csharp
ExitSession,
ExitApp,
SwitchModel,
RefreshModels,
ShowConfig
```

### 8. Tests

Add tests for parser/dispatcher if a separate file is introduced.

Suggested test file:

```text
Omicron.Core.Tests? no — CLI tests do not exist yet.
```

Currently there is no `Omicron.CLI.Tests` project. Options:

1. Keep first pass manually validated.
2. Add `Omicron.CLI.Tests` for command parsing only.
3. Move slash-command parser into `Omicron.Core` if it should be shared later.

Recommendation:

For the first pass, add CLI-only code and manually validate. If slash command logic grows, add `Omicron.CLI.Tests` or move parser-only pieces to a testable core abstraction.

## Implementation Order

### Pass 1: Basic commands, no model switching

1. Add slash command dispatcher/result/context in `Omicron.CLI`.
2. Change `ChatLoop` to return `ChatLoopResult`.
3. Implement:
   - `/help`
   - `/model`
   - `/status`
   - `/tools`
   - `/events [n]`
   - `/provider-state`
   - `/clear-state`
   - `/reset`
   - `/exit`
   - `/quit`
4. Preserve bare `exit`, `reset`, and `?` aliases.
5. Run build/test.
6. Manual CLI validation.

### Pass 2: Model/config commands

1. Extract visible model-list building into a helper.
2. Add `/models`.
3. Add `/switch [n]` returning a switch result to the outer loop.
4. Add `/refresh` returning refresh result or directly refreshing.
5. Add `/config` returning config result.
6. Manual validation.

## Acceptance Criteria

Pass 1 is complete when:

- slash commands work during chat without sending text to the model;
- `/status` shows current provider/API/storage/previous-response support;
- `/provider-state` accurately reflects current session/model provider state;
- `/events` reads from `IEventSink` / `EventLog`;
- `/reset` and bare `reset` behave identically;
- `/exit` and bare `exit` return to model picker;
- `/quit` exits the app;
- build/test pass with no warnings.

Pass 2 is complete when:

- `/models` displays the current visible model list;
- `/model <n|key>` switches to a new model by creating a new session;
- the initial startup model picker is removed; startup selects the last-used visible model or first visible model;
- `/refresh` refreshes model discovery;
- `/config` opens config menu;
- switching models does not preserve provider continuation state across sessions unless explicitly supported later.

## Notes for Future Work

- Eventually connect slash commands to the existing `ICommandRegistry` so commands can be contributed by extensions.
- A future TUI can reuse command definitions but render richer command output.
- Persisting sessions/transcripts later may require command events such as `CommandInvokedEvent`.
