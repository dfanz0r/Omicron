# Implementation Plan 0008.5: Tree-Sitter Core Infrastructure

Status: Proposed
Target: Build the shared parser infrastructure that both highlighting (Plan 8) and semantic analysis (Plan 10) will use.

## Purpose

Plan 8 Phase F introduces tree-sitter for syntax highlighting. Plan 10 Phase E introduces tree-sitter for semantic analysis (definitions, references, symbol indexing). Both need the same foundational infrastructure: parser loading, query compilation, language registry, and worker process management. This plan extracts that shared foundation so it is built **once** and reused by both highlighting and semantic analysis pipelines.

This plan is a **dependency** of Plan 8 Phase F and Plan 10 Phase E. It should be implemented before or in parallel with those phases.

## Primary RFCs

- RFC 0013 — Content Parsing, Markdown Rendering, and Syntax Highlighting
- RFC 0012 — Agent Orchestration, VFS Locking, and Edit Harness
- RFC 0009 — Implementation Roadmap

## Reference Analysis

`docs/reports/0002-tree-sitter-system-analysis.md` — key findings:

- **OpenTUI** uses a Web Worker for off-thread parsing with debounced edit queues and lazy parser loading.
- **Zed** compiles 10 query types per language (`highlights.scm`, `definitions.scm`, `references.scm`, etc.).
- **Dirac/KiloCode** cache queries by `langName:queryText` and use `query.captures()` for result extraction.
- **oh-my-pi** demonstrates native Rust tree-sitter usage with `AstNode` / `WalkEvent` visitor patterns.
- **Key insight:** Both highlighting and semantic analysis start from the same parse tree but run different query files.

## Depends On

- Plan 7 (`Utf8TextStore`, `TerminalFrame`, `TextStyle` — for highlight output integration)
- Plan 3.1 (`TextLineSplitter` — for line-oriented context)
- Plan 5 (`ContentBlock` — for code block language tags)

## Non-Goals

- No GUI text editor features (bracket matching, indentation, folding, outlining)
- No real-time collaborative editing
- No custom grammar authoring
- No language server protocol (LSP) integration
- No semantic analysis for languages without tree-sitter parsers
- No Roslyn integration (tree-sitter C# grammar replaces Roslyn for Plan 10)

## Guiding Principles

1. **Parse once, query many times.** One parse tree serves both highlighting and semantic analysis.
2. **Worker-based parsing.** Keep parsing off the main thread to avoid UI jank.
3. **Lazy parser loading.** Only load WASM parsers for languages actually encountered.
4. **Query caching.** Compiled queries are cached by `langName:queryText` and never shared across grammars.
5. **JSON protocol.** Worker communicates with .NET host via a simple, stable JSON protocol.

## Phase A: Worker Process and Protocol

### Goals
Launch a background worker process (Node.js or Deno) that hosts web-tree-sitter. Define the JSON protocol between .NET host and worker.

### Deliverables

#### A1. `TreeSitterWorker`
```csharp
namespace Omicron.Core.Parsing.TreeSitter;

public sealed class TreeSitterWorker : IDisposable
{
    public TreeSitterWorker(string nodePath, string workerScriptPath);

    /// <summary>Send a request and await the JSON response.</summary>
    public Task<JsonElement> SendAsync(string method, JsonElement payload, CancellationToken ct);

    /// <summary>Send a fire-and-forget notification.</summary>
    public void Notify(string method, JsonElement payload);

    public bool IsRunning { get; }
    public event EventHandler<WorkerCrashedEventArgs>? Crashed;

    public void Dispose();
}
```

- Launches `node worker.js` as a child process.
- Communicates over stdin/stdout with newline-delimited JSON (NDJSON).
- Each request has a unique `id`; responses are matched by `id`.
- Notifications have no `id` and expect no response.
- If the process crashes, raise `Crashed` event. Auto-restart on next `SendAsync`.
- If the worker script is missing, `IsRunning` is false and all operations throw `InvalidOperationException`.

#### A2. `ITreeSitterWorkerProtocol`
```csharp
namespace Omicron.Core.Parsing.TreeSitter;

public static class TreeSitterProtocol
{
    // Requests
    public const string Initialize = "initialize";
    public const string LoadParser = "loadParser";
    public const string Parse = "parse";
    public const string Edit = "edit";
    public const string GetHighlights = "getHighlights";
    public const string GetCaptures = "getCaptures";
    public const string DisposeTree = "disposeTree";

    // Notifications
    public const string Ping = "ping";
}
```

Message shapes:
```json
// Request
{"id": 1, "method": "loadParser", "payload": {"language": "typescript", "wasmPath": "..."}}

// Response
{"id": 1, "result": {"loaded": true}}

// Error
{"id": 1, "error": {"code": "PARSER_NOT_FOUND", "message": "..."}}
```

#### A3. Worker script (`worker.js`)
```javascript
// Minimal Node.js worker script
const Parser = require('web-tree-sitter');

const parsers = new Map();   // lang → Parser
const trees = new Map();     // treeId → Tree
const queries = new Map();   // queryKey → Query

async function handleMessage(msg) {
  switch (msg.method) {
    case 'initialize': await Parser.init(); return { ok: true };
    case 'loadParser': return await loadParser(msg.payload);
    case 'parse': return await parseCode(msg.payload);
    case 'edit': return await editTree(msg.payload);
    case 'getHighlights': return await getHighlights(msg.payload);
    case 'getCaptures': return await getCaptures(msg.payload);
    case 'disposeTree': disposeTree(msg.payload); return { ok: true };
  }
}
```

- Loads `web-tree-sitter` npm package.
- Maintains `Parser`, `Tree`, and `Query` caches.
- Handles `tree.edit()` for incremental updates.
- `getHighlights` runs `highlights.scm` query and returns capture ranges.
- `getCaptures` runs an arbitrary query file and returns raw captures.

## Phase B: Parser Manager

### Goals
Manage WASM parser lifecycle: discovery, loading, and caching.

### Deliverables

#### B1. `ParserManager`
```csharp
namespace Omicron.Core.Parsing.TreeSitter;

public sealed class ParserManager
{
    public ParserManager(TreeSitterWorker worker, string parserSearchPath);

    public async ValueTask EnsureLoadedAsync(string language, CancellationToken ct);
    public bool IsLoaded(string language);
    public IReadOnlyList<string> LoadedLanguages { get; }
}
```

- `parserSearchPath`: directory containing `tree-sitter-{lang}.wasm` files.
- Searches for `{searchPath}/tree-sitter-{language}.wasm`.
- If not found, searches `{searchPath}/tree-sitter-wasms/out/tree-sitter-{language}.wasm` (KiloCode layout).
- Sends `loadParser` to worker; caches result.
- Thread-safe: concurrent calls for the same language coalesce into one load.

#### B2. Bundled parser strategy
Ship Tier-1 parser WASM files as embedded resources or alongside the binary:
```text
runtimes/
  tree-sitter-wasms/
    tree-sitter-c_sharp.wasm
    tree-sitter-typescript.wasm
    tree-sitter-javascript.wasm
    tree-sitter-python.wasm
    tree-sitter-rust.wasm
    tree-sitter-go.wasm
    tree-sitter-java.wasm
    tree-sitter-html.wasm
    tree-sitter-css.wasm
    tree-sitter-markdown.wasm
    tree-sitter-yaml.wasm
    tree-sitter-json.wasm
    tree-sitter-toml.wasm
    tree-sitter-sql.wasm
    tree-sitter-bash.wasm
```

- At startup, extract embedded WASMs to a temp directory if not already present.
- Set `parserSearchPath` to that temp directory.

### Tests
- `ParserManager_LoadsParser_OnFirstUse`
- `ParserManager_Loaded_ReturnsTrueAfterLoad`
- `ParserManager_ConcurrentLoad_Coalesces`
- `ParserManager_MissingParser_Throws`
- `ParserManager_BundledWASM_ExtractsToTemp`

### Acceptance Criteria
- `EnsureLoadedAsync` loads a WASM parser on first use.
- Concurrent loads for the same language do not race.
- Missing parser throws a clear error.
- Bundled WASMs are extracted and discoverable.

## Phase C: Query Manager

### Goals
Load, compile, and cache `.scm` query files per language.

### Deliverables

#### C1. `QueryManager`
```csharp
namespace Omicron.Core.Parsing.TreeSitter;

public sealed class QueryManager
{
    public QueryManager(TreeSitterWorker worker, string querySearchPath);

    public async ValueTask<string> LoadQueryAsync(string language, string queryType, CancellationToken ct);
    public bool IsCached(string language, string queryType);
}
```

- `queryType`: `"highlights"`, `"definitions"`, `"references"`, `"injections"`, etc.
- Searches `{querySearchPath}/{language}/{queryType}.scm`.
- Sends query text to worker for compilation.
- Caches compiled queries in worker memory (keyed by `langName:queryText`).
- **Important:** Queries are grammar-specific. A query compiled for TypeScript cannot be reused for JavaScript, even if the query text is identical. The cache key must include the language name.

#### C2. Query file layout
```text
tree-sitter-queries/
  csharp/
    highlights.scm
    definitions.scm
    references.scm
  typescript/
    highlights.scm
    definitions.scm
    references.scm
  python/
    highlights.scm
    definitions.scm
    references.scm
  markdown/
    highlights.scm
    injections.scm
```

- Query files are plain text `.scm` files shipped as embedded resources.
- Extracted to temp directory alongside parser WASMs.

### Tests
- `QueryManager_LoadsHighlightsQuery`
- `QueryManager_LoadsDefinitionsQuery`
- `QueryManager_CachesQuery`
- `QueryManager_WrongGrammar_ThrowsOnCompile`

### Acceptance Criteria
- `LoadQueryAsync` loads and returns query text.
- Worker caches compiled queries by `langName:queryText`.
- Query files are discoverable from embedded resources.

## Phase E: Integration with Plan 8 and Plan 10

### Goals
Wire the core infrastructure into the highlighting and semantic analysis consumers.

### Deliverables

#### E1. Plan 8 integration (highlighting)
```csharp
// In Plan 8's SyntaxHighlightingEngine:
public sealed class TreeSitterSyntaxHighlighter : ISyntaxHighlighter
{
    private readonly TreeSitterClient _client;
    private readonly LanguageRegistry _registry;

    public async Task<IReadOnlyList<SyntaxToken>> TokenizeAsync(
        ReadOnlyMemory<byte> utf8Code, string language)
    {
        var highlights = await _client.GetHighlightsAsync(language, utf8Code);
        return highlights.Select(h => new SyntaxToken(h.StartOffset, h.EndOffset - h.StartOffset, MapGroupToScope(h.Group))).ToList();
    }
}
```

#### E2. Plan 10 integration (semantic analysis)
```csharp
// In Plan 10's TreeSitterAstContextProvider:
public async Task<SymbolIndex> BuildIndexAsync(WorkspacePath path, string language, ReadOnlyMemory<byte> source)
{
    var captures = await _client.GetCapturesAsync(language, source, queryType: "definitions");
    var symbols = captures.Select(c => new SymbolInfo(c.Name, c.Kind, c.LineStart, c.LineEnd, c.ContainingType)).ToList();
    return new SymbolIndex(symbols);
}
```

#### E3. Shared `TreeSitterClient`
Both Plan 8 and Plan 10 use the same `TreeSitterClient` instance:
```csharp
// In OmicronHost composition:
public TreeSitterClient TreeSitter { get; }

// Constructor:
TreeSitter = new TreeSitterClient(
    new TreeSitterWorker(nodePath, workerScriptPath),
    new ParserManager(worker, parserSearchPath),
    new QueryManager(worker, querySearchPath),
    new LanguageRegistry());
```

### Tests
- `Integration_HighlightCSharp_ReturnsTokens`
- `Integration_DefineCSharp_ReturnsSymbols`
- `Integration_ParseTwice_ReusesTree`

### Acceptance Criteria
- Plan 8's `TreeSitterSyntaxHighlighter` produces `SyntaxToken` lists from tree-sitter captures.

## Risks and Mitigations

| Risk | Mitigation |
|------|------------|
| Node.js/Deno not installed on target machine | Ship a standalone worker executable or document Node.js as a runtime dependency. |
| WASM parser files are large | Only ship Tier-1 parsers; lazy-load others from network or optional packages. |
| Worker process overhead is high | Benchmark against in-process WASM (Wasmtime) as a future alternative. |
| Query files are grammar-specific and fragile | Version query files with parser versions; validate on load. |
| NDJSON protocol is brittle | Add length-prefixed framing or validate JSON before parsing. |
| Concurrent access to worker races | Use request ID matching + async queue on the host side. |
