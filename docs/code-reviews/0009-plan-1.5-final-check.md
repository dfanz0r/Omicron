## Remaining Minor Findings

### 1. Baseline event-delivery section still says async stream yields reset

File: `docs/rfcs/IMPLEMENTATION-BASELINE.md`

The CLI section was corrected, but the earlier `Event Delivery Model` section still says:

```text
Async stream ... yields session-scoped events for live UI rendering: turns, user messages, assistant deltas, tool invocations, errors, reset.
```

This should remove `reset`, because `Reset()` is synchronous and sink-only.

Suggested wording:

```text
Async stream ... yields session-scoped events for live UI rendering: turns, user messages, assistant deltas, tool invocations, errors.
Reset is synchronous and emits SessionResetEvent only to the sink.
```

### 2. Baseline provider-state section does not mention `ClearSession()` return behavior

File: `docs/rfcs/IMPLEMENTATION-BASELINE.md`

The provider-state section mentions `Clear()` returning `bool`, but not the new `ClearSession()` contract.

Suggested addition:

```text
ClearSession() returns the provider-state keys removed for that session.
```

### 3. In-memory `ClearSession()` contract is slightly stronger than implementation under concurrency

File: `Omicron.Core/Sessions/ProviderState.cs`

The interface says:

```csharp
IReadOnlyList<ProviderStateKey> ClearSession(SessionId sessionId);
```

with doc:

```text
Returns the keys that were removed.
```

The in-memory implementation currently gathers keys, attempts removal, and returns the preselected keys even if a concurrent operation removed one first:

```csharp
foreach (var key in keysToRemove)
    _states.TryRemove(key, out var _);

return keysToRemove;
```

For the current in-memory MVP this is acceptable, but if the contract means *actually removed*, it should return only successful removals:

```csharp
var removed = new List<ProviderStateKey>();
foreach (var key in keysToRemove)
{
    if (_states.TryRemove(key, out _))
        removed.Add(key);
}
return removed;
```

This is not a Plan 2 blocker unless concurrent provider-state mutation becomes expected.

### 4. Missing direct tests for `ClearSession()` returned keys/reasons

Files:

- `Omicron.Core.Tests/ProviderStateTests.cs`

The new tests cover the previous findings well, but there is still no direct test that:

- `InMemoryProviderConversationStateStore.ClearSession()` returns the removed keys;
- `ProviderStateManager.ClearSession(..., reason)` emits one clear event per removed key with that reason.

Low priority, but cheap to add if another polish pass happens.
