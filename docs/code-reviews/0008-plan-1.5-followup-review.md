## Verification Summary

The claimed 0007 fixes are largely present in code:

- Event delivery model is documented in `AgentSession` and `IMPLEMENTATION-BASELINE.md`.
- `SessionEventWriter` docs no longer claim that it stamps IDs/timestamps.
- `ProviderStateManager.Set()` normalizes keys before storage/event emission and returns the normalized state.
- `IProviderConversationStateStore.Clear()` returns `bool` and `ProviderStateManager.Clear()` only emits clear events when a key was removed.
- `ProviderStateUpdatedEvent` and `ProviderStateClearedEvent` now carry `Reason`.
- `IEventSink.EmitBatch()` returns stamped events.

Overall, the Plan 1.5 cleanup is in good shape. The remaining items are documentation/test-coverage/API-shape polish rather than blockers.

## Remaining Findings

### 1. `AgentSession` event-delivery doc says reset is yielded, but `Reset()` is sink-only

File: `Omicron.Core/Sessions/AgentSession.cs`

The class XML doc says the async stream yields:

```text
turns, user messages, assistant deltas, tool invocations, errors, reset
```

But `Reset()` is a synchronous method and emits `SessionResetEvent` only to the sink. It is not yielded from `PromptAsync()` or `ContinueAsync()`.

Recommendation:

Update the doc to say reset events are emitted to `IEventSink`, not yielded by the async stream. This keeps the two-channel model accurate.

---

### 2. Baseline says CLI handles execution/provider-state events, but the current CLI cannot receive them through `PromptAsync()`

Files:

- `docs/rfcs/IMPLEMENTATION-BASELINE.md`
- `Omicron.CLI/Program.cs`

The baseline says the CLI event stream dispatcher handles:

```text
ExecutionStartedEvent, ExecutionCompletedEvent, ProviderStateUpdatedEvent, ProviderStateClearedEvent
```

`Program.cs` has switch cases for these event types, but `ReadSessionOutput()` only iterates `session.PromptAsync(...)`. Per the new event-delivery model, nested service events go directly to `IEventSink` and are not yielded from `PromptAsync()`. Therefore those switch cases are currently unreachable unless event routing changes later.

Recommendation:

Either:

- update the baseline to say the CLI currently dispatches only yielded session events and does not live-render nested sink-only events; or
- implement event-sink subscription/streaming if the CLI should live-render execution/provider-state events.

Given the current Plan 1.5 scope, documentation cleanup is enough.

---

### 3. New behavior lacks direct tests

Files:

- `Omicron.Core.Tests/ProviderStateTests.cs`
- `Omicron.Core.Tests/EventSinkTests.cs`

The build passes, but the new review fixes are not directly asserted:

- `ProviderStateManager.Set()` returns/emits normalized keys when given a manually constructed mixed-case key.
- `ProviderStateManager.Clear()` does not emit an event for a missing key.
- `ProviderStateUpdatedEvent.Reason` / `ProviderStateClearedEvent.Reason` are populated.
- `IEventSink.EmitBatch()` returns stamped events in sequence order.

Recommendation:

Add small tests for these. This will prevent regressions as Plan 2 starts using provider state more heavily.

---

### 4. `IProviderConversationStateStore.ClearSession()` still cannot report exact removed keys

Files:

- `Omicron.Core/Sessions/ProviderState.cs`
- `Omicron.Core/Sessions/ProviderStateManager.cs`

`Clear()` now returns `bool`, but `ClearSession()` still returns `void`. The manager currently does:

```csharp
var keys = _store.GetSessionKeys(sessionId);
_store.ClearSession(sessionId);
foreach (var key in keys) emit cleared event;
```

For the in-memory store this is acceptable. For a future persistent/concurrent store, it can emit events based on a pre-clear snapshot rather than the exact set actually removed.

Recommendation:

Before persistence, consider changing the store contract to:

```csharp
IReadOnlyList<ProviderStateKey> ClearSession(SessionId sessionId);
```

Then `ProviderStateManager.ClearSession()` can emit exactly one event per removed key.

This is not required before Plan 2 unless Plan 2 expects concurrent provider-state mutation.

---

### 5. `ProviderStateKey.Create()` still lacks argument validation

File: `Omicron.Core/Sessions/ProviderState.cs`

`providerName.ToLowerInvariant()` will throw a `NullReferenceException` if called with null, and empty provider/model IDs are accepted.

Recommendation:

Add explicit validation for public API clarity:

```csharp
ArgumentException.ThrowIfNullOrWhiteSpace(providerName);
ArgumentException.ThrowIfNullOrWhiteSpace(modelId);
```

Low priority, but cheap to fix.

## Recommendation

No major blocker remains. I would do one final small polish pass before Plan 2:

1. Correct the reset/yield wording in `AgentSession` docs.
2. Correct the CLI baseline wording for sink-only nested events.
3. Add tests for normalized provider-state events, conditional clear events, event reasons, and `EmitBatch()` return values.
4. Optionally make `ClearSession()` return removed keys and add provider/model argument validation.

After that, Plan 2 can safely begin.
