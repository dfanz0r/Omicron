## New Findings

### Finding A: CLI metadata refresh can delay startup for the default `HttpClient` timeout

**Severity:** Medium  
**Files:** `Omicron.CLI/Program.cs`, `Omicron.Core/OmicronHost.cs`

The CLI now awaits metadata refresh on startup:

```csharp
await host.RefreshModelMetadataAsync();
```

This satisfies the requirement that `models.dev` be utilized by the CLI. However, because no timeout is applied, a slow network or stalled endpoint can delay startup until the default `HttpClient.Timeout` (typically 100 seconds).

The plan required startup to remain usable when `models.dev` is unavailable. Fail-closed behavior handles errors, but not slow/hung responses quickly enough for CLI UX.

Recommended fix:

```csharp
using var metadataCts = new CancellationTokenSource(TimeSpan.FromSeconds(2));
await host.RefreshModelMetadataAsync(metadataCts.Token);
```

or make `OmicronHost.RefreshModelMetadataAsync` accept/own a configurable metadata timeout. Cancellation caused by this metadata timeout should be swallowed by the CLI as a non-fatal metadata miss, while user cancellation should still propagate if/when a real app cancellation token exists.

### Finding B: `OmicronHost` creates an owned `HttpClient` but is not disposable

**Severity:** Low/Medium  
**File:** `Omicron.Core/OmicronHost.cs`

`OmicronHost` now does:

```csharp
_metadataHttp = httpClient ?? new HttpClient();
```

If the host creates the client, it should either dispose it or explicitly document that `OmicronHost` intentionally keeps it for process lifetime. Since `OmicronHost` is a long-lived process composition root in the CLI, this is not an immediate leak, but it becomes relevant for tests, embedded hosts, and future multi-host scenarios.

Recommended options:

1. Make `OmicronHost : IDisposable` and dispose only internally-created clients.
2. Prefer requiring/injecting metadata sources or an external `HttpClient` factory later.
3. Document process-lifetime ownership if intentionally not disposable for MVP.

### Finding C: Pricing tests assert presence but not values

**Severity:** Low / direct test improvement  
**File:** `Omicron.Core.Tests/ModelMetadataTests.cs`

The pricing tests currently assert only non-null values. They should assert exact expected values so conversion behavior is pinned down.

Example:

```csharp
Assert.Equal(2.5m, gpt4o.InputPricePerMillionTokens);
Assert.Equal(10.0m, gpt4o.OutputPricePerMillionTokens);
```

If small per-token values should be multiplied by 1,000,000, add a separate test with values below `1m` and assert the converted result.
