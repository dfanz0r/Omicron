## Executive Summary

Plan 3.8 added the major pieces needed for metadata-backed model context display:

- `ModelsDevMetadataSource` now fetches/parses `https://models.dev/api.json`.
- Context/output/capability fields are mapped into `ModelMetadata`.
- `OmicronHost.RefreshModelMetadataAsync()` layers static + models.dev sources.
- `ModelCatalogExtensions` exposes frontend-safe metadata/effective context helpers.
- CLI `/model` and `/models` display metadata-backed context values when metadata exists.
- Build and tests are clean: 406 passing.

However, there are important gaps before this can be considered fully complete:

1. The CLI never calls `RefreshModelMetadataAsync()`, so `models.dev` metadata is not actually loaded in normal CLI use.
2. `ModelsDevMetadataSource` strips any model ID prefix before `/`, which breaks provider-routed IDs such as OpenRouter `openai/gpt-*` models.
3. Pricing mapping likely looks for the wrong field name (`pricing` instead of models.dev `cost`) and is untested.
4. There are no tests for `ModelCatalogExtensions` or CLI display fallback/metadata-preference behavior.
5. Minor resource/API issues: `JsonDocument` is not disposed, and host refresh creates a new `HttpClient` per call.
6. `RefreshMetadataAsync` XML docs still say “Never throws” despite intentionally propagating cancellation.

## Findings

### Finding 1: CLI never refreshes model metadata, so `models.dev` is not used in normal CLI use

**Severity:** High  
**Files:** `Omicron.CLI/Program.cs`, `Omicron.Core/OmicronHost.cs`

`OmicronHost.RefreshModelMetadataAsync()` exists, but search shows it is never called outside its declaration:

```text
Omicron.Core/OmicronHost.cs:115: public async ValueTask<int> RefreshModelMetadataAsync(...)
```

This means normal CLI startup still only has static/discovery metadata. The CLI display code can consume metadata, but no `models.dev` metadata is loaded.

**Impact:** The main Plan 3.8 goal — “models.dev is utilized to provide data for the CLI frontend” — is not met in the actual CLI runtime path.

**Recommended fix:** In CLI startup, after model discovery/catalog setup, call host metadata refresh best-effort:

```csharp
try
{
    await host.RefreshModelMetadataAsync(ct);
}
catch (OperationCanceledException) { throw; }
catch { /* non-fatal metadata refresh failure */ }
```

If startup latency is a concern, use a short timeout or add an explicit refresh command, but some CLI path must invoke it for `/model` and `/models` to show models.dev data.

### Finding 2: Model ID normalization is too aggressive for routed provider model IDs

**Severity:** High  
**File:** `Omicron.Core/Models/ModelsDevMetadataSource.cs`

Current code strips everything before `/` for any model ID containing `/`:

```csharp
var normalizedId = modelId;
if (normalizedId.Contains('/'))
    normalizedId = normalizedId[(normalizedId.IndexOf('/') + 1)..];
```

This works for an entry like provider `anthropic`, model id `anthropic/claude-sonnet-4`, but it breaks routed IDs that intentionally contain another provider prefix, e.g. OpenRouter-style IDs:

```text
provider: openrouter
model id: openai/gpt-5.4-mini
```

Omicron’s static OpenRouter model uses:

```csharp
Model.Id = "openai/gpt-5.4-mini"
ProviderName = "openrouter"
```

The current parser would normalize `openai/gpt-5.4-mini` to `gpt-5.4-mini`, so `ModelCatalogExtensions.GetMetadata(model)` will not find it by `(model.Id, model.ProviderName)`.

**Recommended fix:** Only strip a slash prefix if it matches the provider name:

```csharp
if (normalizedId.StartsWith(providerName + "/", StringComparison.OrdinalIgnoreCase))
    normalizedId = normalizedId[(providerName.Length + 1)..];
```

Or preserve both canonical and alias IDs in metadata lookup.

**Required test:** Add a test proving provider `openrouter`, model id `openai/gpt-5.4-mini` remains `openai/gpt-5.4-mini`.

### Finding 3: Pricing mapping likely uses the wrong models.dev field name and is untested

**Severity:** Medium  
**File:** `Omicron.Core/Models/ModelsDevMetadataSource.cs`

The parser checks:

```csharp
if (entry.TryGetProperty("pricing", out var pricing))
```

Models.dev documentation/reference describes pricing under `cost.*`, not `pricing.*`.

**Impact:** Input/output price metadata may never populate from real `models.dev` responses.

**Recommended fix:** Support `cost` and optionally retain `pricing` as a fallback if desired:

```csharp
if (entry.TryGetProperty("cost", out var cost) || entry.TryGetProperty("pricing", out cost))
```

**Required test:** Add a sample JSON test with `cost.input` / `cost.output` verifying `InputPricePerMillionTokens` and `OutputPricePerMillionTokens` are populated.

### Finding 5: `JsonDocument` returned by `GetFromJsonAsync<JsonDocument>` is not disposed

**Severity:** Low  
**File:** `Omicron.Core/Models/ModelsDevMetadataSource.cs`

Current code:

```csharp
var doc = await _http.GetFromJsonAsync<JsonDocument>(_endpoint, ct);
if (doc is null) return Array.Empty<ModelMetadata>();

return Parse(doc.RootElement);
```

`JsonDocument` should be disposed to release pooled memory.

**Recommended fix:**

```csharp
using var doc = await _http.GetFromJsonAsync<JsonDocument>(_endpoint, ct);
if (doc is null) return Array.Empty<ModelMetadata>();
return Parse(doc.RootElement);
```

This is safe because `Parse` materializes metadata before the document is disposed.

### Finding 6: Host refresh creates a new `HttpClient` per refresh

**Severity:** Low/Medium  
**File:** `Omicron.Core/OmicronHost.cs`

`RefreshModelMetadataAsync` constructs:

```csharp
new ModelsDevMetadataSource()
```

The source creates a new `HttpClient` when none is injected. This is fine for one-off tests but not ideal if refresh becomes user-triggered or repeated.

**Recommended fix:** Make the host own/reuse a metadata `HttpClient` or accept configured metadata sources in the host constructor.

---

### Finding 7: `RefreshMetadataAsync` XML docs are still inaccurate

**Severity:** Low / direct cleanup  
**File:** `Omicron.Core/Models/ModelCatalogService.cs`

The XML doc still says:

```csharp
/// Never throws — returns the count of metadata entries loaded.
```

But cancellation is intentionally rethrown, and empty refresh returns the previous metadata count.

**Recommended fix:** Update wording to match behavior:

```csharp
/// Source failures are skipped, but caller cancellation is propagated.
/// If no source returns metadata, preserves the previous metadata snapshot.
/// Returns the active metadata count after refresh/preservation.
```
