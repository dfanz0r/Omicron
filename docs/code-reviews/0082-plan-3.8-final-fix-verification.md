## New Direct Finding

### Finding A: `OmicronHost` disposes externally injected `HttpClient` and CLI does not dispose host

**Severity:** Medium / direct fix  
**Files:** `Omicron.Core/OmicronHost.cs`, `Omicron.CLI/Program.cs`

`OmicronHost` now accepts an optional `HttpClient`:

```csharp
public OmicronHost(string workspaceRoot, ISessionStore? sessionStore = null, HttpClient? httpClient = null)
```

but stores it directly and always disposes it:

```csharp
_metadataHttp = httpClient ?? new HttpClient { Timeout = TimeSpan.FromSeconds(5) };
...
_metadataHttp?.Dispose();
```

This means callers that inject their own shared `HttpClient` will unexpectedly lose ownership when the host is disposed.

Also, CLI currently creates the host without disposing it:

```csharp
var host = new OmicronHost(Environment.CurrentDirectory, sessionStore);
```

so internally-created metadata clients are not disposed in the CLI path.

Recommended fix:

```csharp
private readonly bool _ownsMetadataHttp;

public OmicronHost(..., HttpClient? httpClient = null)
{
    if (httpClient is null)
    {
        _metadataHttp = new HttpClient { Timeout = TimeSpan.FromSeconds(5) };
        _ownsMetadataHttp = true;
    }
    else
    {
        _metadataHttp = httpClient;
        _ownsMetadataHttp = false;
    }
}

public void Dispose()
{
    if (!_disposed)
    {
        _disposed = true;
        if (_ownsMetadataHttp)
            _metadataHttp.Dispose();
    }
}
```

and in CLI:

```csharp
using var host = new OmicronHost(Environment.CurrentDirectory, sessionStore);
```

This preserves correct ownership semantics and disposes the internally-created client in normal CLI operation.
