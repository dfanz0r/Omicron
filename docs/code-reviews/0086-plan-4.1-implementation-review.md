## Findings

### Finding 1: Directory listing lost `(binary)` indicator and size column

**Severity:** Medium  
**File:** `BuiltinWorkspaceToolsExtension.cs` (directory listing block, lines ~90–115)

The old `read_path` directory listing used `WorkspaceLlmTextRenderer.RenderDirectory()` which showed:

```text
[DIR] src/  (3 files, 1 dirs)
  [DIR]  subdir/
  [FILE] Program.cs                               142 lines
  [FILE] icon.png                           12 KB  (binary)
```

The new inline rendering shows:

```text
[DIR] src/  (directory)
  subdir/
  Program.cs  (142 lines)
  icon.png
```

Lost: `[FILE]`/`[DIR]` prefixes, file size column, `(binary)` indicator for non-text files. The binary indicator especially matters — we added `TextEncodingDetector` to `WorkspaceVfs.ReadDirectoryAsync` specifically to support this, and the rendering just dropped it.

**Fix:** Restore the old rendering format OR delegate directory listings back to `WorkspaceLlmTextRenderer`. The new code should not have reimplemented directory rendering inline.

### Finding 2: `ModalityUsedEvent` emission is stubbed with TODO

**Severity:** Medium  
**File:** `BuiltinWorkspaceToolsExtension.cs` (lines ~166–176)

```csharp
// TODO: wire ModalityUsedEvent emission when IEventSink is available through context
```

The event type exists, is registered in `OmicronEventRegistry`, and `ContentProcessorContext` already has `IEventSink? EventSink`. The emission code is written but commented out. Without this, Phase 6 (cross-model modality validation) has no data source.

**Fix:** Call `ctx.EventSink?.EmitAsync(new ModalityUsedEvent(...))` using the `SessionId` already on `BuildContext`.

### Finding 3: `TextProcessor` duplicates text rendering instead of delegating

**Severity:** Low  
**File:** `Omicron.Core/IO/Formats/TextProcessor.cs`

The `TextProcessor` re-implements text reading (BOM detection, line splitting, truncation, formatting) instead of delegating to the existing `WorkspaceReadService` / `WorkspaceLlmTextRenderer` pipeline. This:

- Duplicates truncation logic (2000 lines, 50 KB).
- Uses a different text format (`     1| text` instead of the `WorkspaceTextLine` format).
- Creates a second code path that can drift from the main text reading logic.

The existing `read_path` text pipeline is battle-tested. The processor should delegate to it rather than duplicate it.

**Fix:** Have `TextProcessor.ProcessAsync` delegate to `_workspace.ReadPathAsync()` or extract the text formatting into a shared helper. If the processor needs raw bytes access (for the `format: "text"` override case), that's a separate concern from the auto-detect text path.

### Finding 4: `ImageProcessor` redundant modality check

**Severity:** Low  
**File:** `Omicron.Core/IO/Formats/ImageProcessor.cs` (line ~30)

```csharp
bool visionCapable = context.ModelMetadata?.SupportsImages() == true
                     || context.ModelMetadata?.SupportsModality("image") == true;
```

`SupportsImages()` already checks `SupportsModality("image")` AND `SupportsVision`. The second check is redundant.

**Fix:** Remove the redundant `SupportsModality("image")` check. Keep only `SupportsImages()`.

### Finding 5: `TryRegister` catches all exceptions — too broad

**Severity:** Low  
**File:** `Omicron.Core/OmicronHost.cs` (line ~137)

```csharp
catch (Exception ex)
{
    System.Diagnostics.Debug.WriteLine($"[ContentProcessor] Skipped {processor.Id}: {ex.Message}");
}
```

This catches `OutOfMemoryException`, `StackOverflowException`, `NullReferenceException` (from our own code), etc. A bug in a processor constructor would be silently swallowed. Should catch only the specific exception types that represent "dependency not available" — likely `TypeLoadException`, `FileNotFoundException`, or a custom `MissingDependencyException` thrown by the processor itself.

**Fix:** Narrow the catch, or have processors throw a specific exception type for missing dependencies.

### Finding 6: No tests for any new code

**Severity:** Medium (process, implementor responsible)  
**Files:** All new files

The plan's Phase 7 explicitly lists ~30 tests covering: classifier (magic bytes, ZIP subtypes, extension fallbacks), hex dump (format, chunking, edge cases, `0x` parsing), processor registry (resolution, fallback, extension registration), model-aware behavior (base64 vs hex dump per model), `read_path` integration (format overrides, auto mode, text regression), and modality events (emission, persistence, validation). None were implemented.

This is the implementor's responsibility — the plan was clear about test requirements.

**Action for implementor:** Add the Phase 7 tests. Minimum coverage: classifier (all file types), hex dump (format + edge cases), model-aware processor behavior, `read_path` format override paths.
