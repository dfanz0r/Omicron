## New Direct Findings

### Finding A: `RefreshMetadataAsync` should not swallow cancellation

**Severity:** Medium / direct fix  
**File:** `Omicron.Core/Models/ModelCatalogService.cs`

`RefreshMetadataAsync` currently catches all exceptions from metadata sources:

```csharp
try
{
    var entries = await source.LoadAsync(ct);
    inputs.Add(entries);
}
catch
{
    // Source failed closed — skip
}
```

This also catches `OperationCanceledException`, which means caller cancellation can be ignored. Failing closed is appropriate for provider/network errors, but cancellation should normally propagate.

Recommended fix:

```csharp
catch (OperationCanceledException) when (ct.IsCancellationRequested)
{
    throw;
}
catch
{
    // Source failed closed — skip
}
```

Add a small test verifying a source that throws `OperationCanceledException` with a canceled token causes `RefreshMetadataAsync` to throw/cancel instead of returning silently.

### Finding B: Add explicit preservation regression test

**Severity:** Low / direct test improvement  
**File:** `Omicron.Core.Tests/ModelMetadataTests.cs`

The implementation preserves previous metadata when a later refresh produces no entries, but the current tests only check a failing source against an initially empty catalog.

Add a test like:

1. Refresh with `StaticModelMetadataSource`.
2. Capture `catalog.Metadata.Count`.
3. Refresh with `ThrowingMetadataSource` or `ModelsDevMetadataSource`.
4. Assert the count and representative metadata entry are unchanged.

This locks in the new last-known-good behavior.
