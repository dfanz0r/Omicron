# TUI Feature Audit Report

Date: 2025-05-11  
Scope: `Omicron.CLI/Tui/` + `Omicron.Core/Rendering/` TUI-related code  
Method: Manual code review — no explicit TODO/FIXME markers were found; all gaps discovered by tracing usage.

---

## 1. Input Editor (`InputEditorWidget.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 1.1 | **Completions list is stashed but never displayed** | High | `Complete()` sets `_pendingCompletions` when multiple matches exist, but `Render()` does not draw the completion list. The user presses Tab and nothing happens visually. |
| 1.2 | **No input history (Up/Down recall)** | Medium | Standard terminal UX — Up arrow should recall previous prompts. No history stack exists. |
| 1.3 | **No multi-line input** | Medium | Shift+Enter or similar to insert a newline. Currently Enter always submits. |
| 1.4 | **No clipboard paste handling** | Low | Bracketed paste mode exists in `TerminalScope` but is never enabled. `Ctrl+V` / `Ctrl+Shift+V` is not handled. |
| 1.5 | **Completion display does not handle overflow** | Low | If completions exceed screen width, they would wrap. No truncation or paging logic exists. |
| 1.6 | **Cursor style is hardcoded** | Low | Block cursor only. No line or bar cursor option. No blink animation. |

---

## 2. Transcript Viewport (`TranscriptViewportWidget.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 2.1 | **No search / find within transcript** | High | No `/search` or `Ctrl+F` equivalent. Large sessions are unnavigable without scroll. |
| 2.2 | **No copy-to-clipboard** | Medium | Cannot copy a message, code block, or the entire transcript. No selection model exists. |
| 2.3 | **No message selection / highlighting** | Medium | Clicking a message does nothing. No visual focus state for individual messages. |
| 2.4 | **Mouse click does not set scroll position** | Low | Only scroll wheel (ScrollUp/ScrollDown) works. Click-drag or click-to-jump is not implemented. |
| 2.5 | **No timestamps** | Low | Messages have no `CreatedAt` display. Would help orient in long sessions. |
| 2.6 | **No message folding / collapse** | Low | Long assistant messages cannot be collapsed. |
| 2.7 | **Streaming text re-layout on every delta** | Medium | `InvalidateLastBlock()` in `Render()` rebuilds layout for the last block. For fast streaming this is O(n) per frame. `ReflowBlock()` exists in `TranscriptLayoutCache` but is not used here — `RebuildLayout()` is called instead. |

## 3. Status Bar (`StatusBarWidget.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 3.1 | **Gradient text is extremely subtle** | Low | `_textStart` → `_textEnd` spans `(30,25,15)` to `(55,45,30)`. On most terminals this is imperceptible. Users likely see flat dark text. |
| 3.2 | **No interactive elements** | Low | Clicking the status bar does nothing. Could show model info popup, copy token counts, etc. |
| 3.3 | **Error state is text-only** | Low | When API errors occur, only the text changes. No color flash, no icon, no persistent error indicator. |

| 5.2 | **No search / filter** | Medium | Cannot type to filter models. Must arrow through entire list. |
| 5.3 | **No number-key selection** | Medium | Typing `1`, `2`, `3` should jump to that index. Only arrow keys work. |

## 6. API Key Prompt (`TuiApiKeyPrompt.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 6.1 | **No "show key" toggle** | Medium | Cannot temporarily unmask to verify paste. `Ctrl+S` or similar would help. |
| 6.2 | **No validation feedback** | Low | Empty key or suspiciously short key is accepted silently. |

## 7. Slash Command Bridge (`TuiSlashCommandBridge.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 7.1 | **`OnNotice` event is never invoked** | Medium | Event exists but no caller. Could be used for toast-style notifications. Currently generates CS0067 warning. |
| 7.2 | **Console.Out capture is fragile** | Medium | `Console.SetOut(new StringWriter(captured))` redirects stdout but not stderr. Commands writing to `Console.Error` leak outside the TUI. |
| 7.3 | **Command output may overflow transcript** | Low | Large command outputs (e.g. `/events 1000`) append all text. No truncation or paging. |
| 7.4 | **No command help inline** | Low | Typing `/` with no command could show a palette of available commands. Currently requires `/help`. |

## 8. App Layout (`AppLayout.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 8.1 | **No notification / toast system** | Medium | `OnNotice` from `SlashBridge` exists but `AppLayout` does not subscribe to it. No way to show ephemeral status messages. |
| 8.2 | **Session switch does not preserve scroll position** | Low | `SwitchSession` resets transcript and scrolls to bottom. No "restore previous position" for resumed sessions. |
| 8.3 | **Escape during generation only cancels, does not also exit** | Low | When `_isGenerating`, Escape sets status to "cancelled" but does not exit. User must press Escape again. This is intentional but may feel sluggish. |
| 8.4 | **Mouse scroll amount is hardcoded** | Low | `ScrollUp(3)` / `ScrollDown(3)`. No acceleration or configurable scroll speed. |
| 8.5 | **No transcript export from TUI** | Low | No `/export` or similar to save transcript as markdown. |

## 9. Shell / Event Loop (`TuiShell.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 9.1 | **`TargetFps` property exists but frame pacing was removed** | Medium | Original code had `Task.Delay(1000 / TargetFps)` after render. Removed during animation cleanup. Now renders as fast as events arrive — fine for typing, but could burn CPU during streaming. |
| 9.2 | **No render frame budget / slow-frame warning** | Low | No instrumentation to detect if `onRender` + diff + flush exceeds a frame budget. |
| 9.3 | **Mouse tracking is enabled but click-to-focus is not used** | Low | `TerminalScope.UseMouse(_backend)` enables mouse events. Only scroll wheel is handled. Click-to-focus, click-to-select, etc. are not implemented. |
| 9.4 | **No focus management system** | Medium | Only one widget (input) handles keys directly. No focus ring, no tab order, no focus indicator on non-input widgets. |

---

## 10. Terminal Backend (`SystemTerminalBackend.cs`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 10.1 | **Resize detection is polling-based** | Medium | `RefreshSize()` is called on every `backend.Size` access. No SIGWINCH handler on Unix, no console input record parsing on Windows. Resize only detected when the user generates input after resizing. |
| 10.2 | **Bracketed paste mode exists but never enabled** | Low | `TerminalScope.UseBracketedPaste` exists but is not called in `TuiShell.RunAsync`. |
| 10.3 | **No focus event support** | Low | Terminals that support focus in/out (DEC 1004) could pause rendering when unfocused. Not implemented. |
| 10.4 | **Windows `Task.Run` read has no timeout** | Low | If the console handle is invalid (e.g., redirected I/O), `Read` blocks the thread pool thread indefinitely. No cancellation token is passed to the synchronous `Read`. |

## 11. Startup Flow (`Program.cs` — `RunTuiSessionAsync`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 11.1 | **Picker cancellation falls through to error message** | Medium | If user cancels model picker, `selectedModel` is null, and the app prints "No models available" and exits. Should return to CLI mode or show a retry prompt. |
| 11.2 | **API key prompt cancellation also exits** | Medium | Same issue — cancelling the API key prompt leads to "No models available" and exit. |
| 11.3 | **`TuiShell` reused between modal and main loop without full reset** | Medium | `ResetState()` drains render signals but does not reset `TerminalScope` ref counts. Mouse tracking, alternate screen, and hide-cursor are re-acquired on each `RunAsync` call. This mostly works due to ref-counting but is fragile. |
| 11.4 | **No way to create a session without a model** | Low | If no models are visible, the app exits. No "configure API key" flow inside the TUI. |

## 12. Core Rendering (`DifferentialRenderer`, `SwapChain`, `AnsiEncoder`)

| # | Issue | Severity | Notes |
|---|-------|----------|-------|
| 12.1 | **`AnsiEncoder` skips black background (0,0,0)** | Medium | `SetStyle` treats `BgR==0 && BgG==0 && BgB==0` as "terminal default" and emits `\x1b[49m`. This is correct for most terminals but breaks on terminals with non-black default backgrounds (e.g., Solarized). The original code always emitted explicit RGB. |
| 12.2 | **`EmitFullFrame` writes to `width - 1` unconditionally** | Low | `lastCol = width - 1` forces writing every column even if trailing cells are empty. Slightly more output than needed on sparse frames. |
| 12.3 | **No terminal capability detection** | Medium | Assumes 24-bit RGB support everywhere. No fallback to 256-color or 16-color for older terminals. `TerminalCapabilities` class is referenced in docs but does not exist. |
| 12.4 | **`GlyphInternTable` is not cleared on frame clear** | Low | `TerminalFrame.Clear()` calls `_glyphTable.Reset()`. `SwapChain.Swap()` calls `Current.Clear()`. But `DifferentialRenderer.Render()` does NOT copy the glyph table — it passes `source.GlyphTable` directly. This is intentional for performance, but means the back buffer's glyph table may contain stale entries between frames. Not a bug in practice but worth noting. |
